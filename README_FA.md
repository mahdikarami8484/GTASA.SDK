# پروژه GTASA.SDK

<div align="center">

[`فارسی`](./README_FA.md) | [`English`](./README.md)

</div>

پروژه GTASA.SDK یک SDK در حال توسعه بر پایه C++20 برای Grand Theft Auto: San Andreas (GTA:SA) است. هدف این پروژه توسعه یک SDK کامل و توسعه‌دهنده‌ پسند برای کاوش، گسترش و تعامل با ساختارهای داخلی و کدهای C++ بازی است.

در حال حاضر، این پروژه یک فایل DLL 32 بیتی برای ویندوز ایجاد می‌کند که درون فرایند بازی اجرا شده و Runtime مربوط به SDK را راه‌اندازی می‌کند. همچنین امکان بررسی و مدیریت Hookهای توابع، ارسال رویدادها و دسترسی به Wrapperهای منتخب بازی را فراهم می‌کند؛ از جمله بازیکن محلی، Ped، ماتریس‌ها، پیام‌های HUD، پول، سلامت، زره و موارد دیگر.

>این پروژه با هدف یادگیری، مهندسی معکوس، بررسی ساختارهای داخلی بازی، مطالعه تکنیک‌های داخلی‌سازی و درک بهتر نحوه مدیریت و تعامل با حافظه توسعه داده شده است. لطفاً از این پروژه تنها در محیط‌های قانونی و آفلاین استفاده کنید.


## این پروژه چه کاری انجام می‌دهد؟
- به‌صورت یک DLL در فرایند بازی بارگذاری می‌شود و Runtime مربوط به SDK را از طریق DllMain راه‌اندازی می‌کند.
- از Microsoft Detours برای Hook کردن توابع منتخب بازی، Win32 و Direct3D 9 استفاده می‌کند.
- کالبک‌های هوک را از طریق یک باس رویداد مرکزی به رویدادهای SDK تبدیل می‌کند.
- به اسکریپت‌ها اجازه می‌دهد در رویدادهای ران‌تایم عضو شوند و رفتار را بدون سیم‌کشی دستی هر اسکریپت تغییر دهند.
- رپرهای اولیه را برای ساختارهای حافظه مشترک GTA:SA و آدرس‌های توابع فراهم می‌کند.
- شامل اسکریپت‌های نمونه برای دستکاری بازیکن، بهبود حالت پنجره‌ای و Process Affinity است.

## ساختار پروژه

<div dir="ltr">

```text
.
|-- CMakeLists.txt              # تعریف اصلی ساخت با CMake
|-- CMakePresets.json           # پیش‌تنظیم پیکربندی Visual Studio 2022 Win32
|-- libs/
|   `-- Detours/                # وابستگی Microsoft Detours به عنوان یک ساب‌ماژول گیت
|-- scripts/                    # اسکریپت‌های کاربر که به رویدادهای SDK واکنش نشان می‌دهند

|   |-- affinity_script.cpp     # تنظیم افینیتی پروسس (وابستگی پردازنده) پس از راه‌اندازی
|   |-- sample_script.cpp       # اسکریپت نمونه برای بازیکن/HUD/گیم‌پلی
|   `-- windowed_script.cpp     # تنظیم پارامترهای Win32 و D3D9 برای حالت پنجره‌ای
`-- src/
    |-- dllmain.cpp             # نقطه ورود DLL؛ راه‌اندازی و خاموش کردن ران‌تایم SDK
    |-- core/

    |   |-- event/              # کلاس BaseEvent و باس رویداد (EventBus)
    |   |-- game/               # رپرها، آفست‌ها، انتیتی‌ها و هلپرهای HUD برای GTA:SA
    |   |-- hook/               # اینترفیس‌های هوک، ریجستری، مدیر (Manager) و ثبت خودکار
    |   |-- logging/            # لاگر کنسول دیباگ و بافر حلقوی (Circular Buffer)
    |   |-- math/               # انواع داده‌های ریاضی کوچک مانند Vector3
    |   |-- script/             # کلاس پایه اسکریپت و هلپر ثبت خودکار
    |   `-- sdk_runtime.*       # راه‌اندازی ران‌تایم، نصب هوک، و شروع/خاتمه کار رویدادها
    `-- hooks/                  # پیاده‌سازی‌های عینی هوک
        |-- d3d9_hook.*         # هوک کردن تابع IDirect3D9::CreateDevice
        |-- game_loop_hook.*    # هوک کردن توابع فریم/سیستم منتخب در GTA:SA
        |-- player_hook.*       # هوک‌های آزمایشی مربوط به بازیکن/جرم و جنایت
        `-- windows_hook.*      # هوک کردن تابع CreateWindowExA
```
</div>


## جریان ران‌ تایم

1. ویندوز DLL ساخته‌شده را درون پروسس GTA:SA بارگذاری می‌کند.
2. فایل `src/dllmain.cpp` یک ترد مجزای SDK را روی وضعیت `DLL_PROCESS_ATTACH` ایجاد می‌کند.
3. تابع `SDKRuntime::init()` لاگر دیباگ را راه‌اندازی کرده و `GameBase` را از ماژول پروسس فعلی مقداردهی اولیه می‌کند.
4. اسکریپت‌های ثبت‌شده از طریق `AutoRegisterScript<T>` یک رویداد `InitializeEvent` دریافت می‌کنند.
5. هوک‌های ثبت‌شده از طریق `AutoHook<T>` بر اساس اولویت مرتب‌سازی شده و نصب می‌شوند.
6. بخش `HookManager` تمامی هوک‌های Detours را در قالب یک تراکنش فعال می‌کند.
7. کالبک‌های هوک رویدادهایی مانند `ProcessFrameEvent`، `CreateWindowExAEvent` و `CreateDeviceEvent` ایجاد می‌کنند.
8. بخش `EventBus` این رویدادها را به اسکریپت‌های فعال ارسال می‌کند.
9. در هنگام تخلیه، تابع `SDKRuntime::shutdown()` هوک‌ها را غیرفعال کرده، رویداد `ShutdownEvent` را می‌فرستد و لاگ‌گیری را متوقف می‌کند.


## نیازمندی‌ها

- ویندوز (Windows)
- ویژوال استودیو (نسخه 2019 یا جدیدتر توصیه می‌شود) همراه با ورک‌لود "Desktop development with C++"
- ابزار CMake نسخه 3.20 یا جدیدتر
- ابزار Git با پشتیبانی از ساب‌ماژول‌ها (Submodules)
- کیت توسعه Microsoft DirectX SDK (ژوئن 2010) (برنامه نصب‌کننده به طور خودکار متغیر محیطی `DXSDK_DIR` را پیکربندی می‌کند که توسط CMake استفاده می‌شود)
- یک فایل اجرایی/ساختار سازگار با نسخه GTA:SA 1.0 US که با آفست‌های استفاده‌شده در `src/core/game/offsets.h` و آدرس‌های هوک در `src/hooks/` هماهنگ باشد

از آنجا که بازی GTA:SA یک بازی ۳۲ بیتی است، پروژه باید به صورت Win32/x86 ساخته (Build) شود. پیش‌تنظیم (Preset) CMake موجود در پروژه از قبل معماری `Win32` را هدف قرار داده است.


## کلون کردن

مخزن پروژه را به همراه ساب‌ماژول‌ها کلون کنید:

<div dir="ltr">

```powershell
git clone --recursive https://github.com/mahdikarami8484/GTASA.SDK.git
cd GTASA.SDK
```
</div>

اگر از قبل پروژه را بدون ساختار `--recursive` کلون کرده‌اید، ساب‌ماژول Detours را به صورت دستی راه‌اندازی (Initialize) کنید:

<div dir="ltr">

```powershell
git submodule update --init --recursive
```
</div>


## ساخت با استفاده از CMake

از طریق دِوِلوپر پاورشلِ ویژوال استودیو (Visual Studio Developer PowerShell)، دِوِلوپر کامند پرامپت (Developer Command Prompt) یا هر ترمینالی که ابزارهای MSVC در آن پیکربندی شده‌اند، دستورات زیر را اجرا کنید:

<div dir="ltr">

```powershell
cmake --preset msvc-x86
cmake --build build --config Debug
```
</div>

این پیش‌تنظیم (Preset) از موارد زیر استفاده می‌کند:

- تولیدکننده (Generator): به صورت خودکار توسط CMake شناسایی می‌شود (از نسخه فعال MSVC/Visual Studio شما استفاده می‌کند)
- معماری (Architecture): معماری `Win32`
- دایرکتوری ساخت (Build directory): پوشه `build/`
- استاندارد سی‌پلاس‌پلاس: استاندارد C++20

به محض اینکه عملیات ساخت با موفقیت به پایان برسد، تمام خروجی‌های کامپایل‌شده (مانند launcher.exe و GTASA_SDK.dll) در داخل دایرکتوری خروجی ساخت (به عنوان مثال out/Debug/) ایجاد خواهند شد.



## ساخت با استفاده از ویژوال استودیو

1. مخزن پروژه را کلون کرده و ساب‌ماژول‌ها را راه‌اندازی (Initialize) کنید.
2. پوشه مخزن را در Visual Studio 2022 باز کنید و اجازه دهید ویژوال استودیو پروژه را با استفاده از پیش‌تنظیم سی‌میک موجود (`CMakePresets.json`) پیکربندی کند.
3. یک پیکربندی از نوع Win32/x86 را انتخاب کنید.
4. مطمئن شوید که مسیر اینکلود (Include Path) کیت DirectX SDK و ساب‌ماژول Detours در دسترس هستند.
5. تارگت `GTASA_SDK` را بیلد (Build) کنید.



## اجرا و تست کردن

به محض اینکه فرآیند ساخت با موفقیت به پایان رسید، می‌توانید با استفاده از لانچر اختصاصی، کیت SDK را اجرا و تست کنید:

1. به دایرکتوری خروجی ساخت بروید (به عنوان مثال `out/Debug/` یا هر جایی که فایل اجرایی کامپایل‌شده‌ی لانچر در آن قرار دارد).
2. فایل `launcher.exe` را اجرا کنید.
3. یک پنجره انتخاب فایل یا پرامپت ظاهر می‌شود؛ از آن برای انتخاب فایل اجرایی بازی جی‌تی‌ای سان اندرس (`gta_sa.exe`) استفاده کنید.
4. لانچر به طور خودکار بازی را راه‌اندازی کرده و فایل `GTASA_SDK.dll` را در بدو استارت‌آپ به درون پروسس بازی تزریق (Inject) می‌کند.
5. اکنون می‌توانید اسکریپت‌های خود را تست کنید، کنسول ثبت لاگ‌های دیباگ را (در پیکربندی Debug) مشاهده کنید و ویژگی‌های SDK را به صورت زنده درون بازی آزمایش نمایید!


## ساخت یک اسکریپت

اسکریپت‌ها از کلاس `GTASA::SDK::Script` ارث‌بری می‌کنند و رویدادها را از طریق تابع `onEvent` مدیریت می‌نمایند. یک اسکریپت را با ایجاد یک نمونه استاتیک از `AutoRegisterScript<T>` ثبت کنید:

<div dir="ltr">

```cpp
#include "core/script/script.h"
#include "core/script/auto_register_script.h"
#include "core/sdk_runtime.h"

namespace GTASA::SDK {

class MyScript : public Script {
public:
    void onEvent(std::shared_ptr<BaseEvent> event) override {
        if (dynamic_cast<const Events::InitializeEvent*>(event.get())) {
            // Initialize script state here.
        }
    }
};

}

namespace {
    GTASA::SDK::AutoRegisterScript<GTASA::SDK::MyScript> _autoReg;
}
```
</div>

فایل‌های اسکریپت جدید را در مسیر `scripts/` قرار دهید. ابزار CMake به طور خودکار تمامی فایل‌های تعبیه‌شده در مسیر `scripts/*.cpp` را از طریق دستور `file(GLOB_RECURSE ...)` وارد پروژه می‌کند.

## نکات و ایمنی

- آدرس‌ها و آفست‌ها (Offsets) وابسته به نسخه خاصی از بازی هستند. اگر فایل اجرایی (Executable) بازی شما متفاوت باشد، هوک‌ها یا خواندن از حافظه ممکن است باعث کرش کردن (Crash) بازی شوند.
- نسخه‌های دیباگ (Debug builds) یک کنسول اختصاصی برای ثبت لاگ‌های SDK تخصیص می‌دهند؛ در حالی که نسخه‌های نهایی (Release builds) از طریق فلگ `NDEBUG` مسیر کنسول لاگر را نادیده می‌گیرند.
- برخی از هوک‌ها جنبه آزمایشی دارند و ممکن است در کد پروژه ناقص یا غیرفعال باشند.
- فعالیت‌های مربوط به مهندسی معکوس خود را صرفاً جنبه آموزشی، محلی (Local) نگه دارید و به لایسنس‌های نرم‌افزاری و قوانین خدمات آنلاین احترام بگذارید.
